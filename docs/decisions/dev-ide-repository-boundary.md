# dev-ide 分支与仓库根边界决策

> 状态：Decision；接受日期：2026-08-23。

## 1. Decision

1. 当前 `as-aosp` Git 仓库继续作为产品仓库，不建立新的 Git 仓库。
2. `dev-ide` 分支只承载新插件方案，仓库根目录就是新项目根目录。
3. `dev-ide` 不创建嵌套的 `aosp-ide/` 工程目录。
4. 历史 Gradle/CMake/脚本方案只保留在 `aosp` 分支，不复制为兼容目录。
5. 新组件和目录不使用容易与 AI 产品混淆的名称；远程能力使用 `remote-execution/`。

## 2. Why

- 当前仓库已有用户、Star、Issue 和分发入口，迁移新仓库会损失连续性。
- 分支已经提供历史实现隔离，无需在新分支继续承担双方案维护成本。
- 仓库根直接表达新产品边界，避免多一层无意义目录。
- 清晰名称可以减少用户和维护者对组件职责的误解。

## 3. Consequences

- 根 README、构建入口、CI 和发布流程全部面向新方案重建。
- 需要参考旧脚本时跨分支读取，不在生产源码中建立兼容依赖。
- 删除旧实现只影响 `dev-ide`；切换到 `aosp` 分支仍可恢复。

## 4. Revisit conditions

只有当前仓库无法继续满足权限、发布或治理要求时，才重新讨论物理仓库迁移。
